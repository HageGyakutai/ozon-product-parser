## Требует реального Ozon и Gmail

| Компонент | Что ещё доказать |
|---|---|
| Вход через `data.ozon.ru` | Фактические элементы формы и подтверждение входа по защищённому ресурсу, а не одному URL. Сейчас Playwright получает antibot до формы. |
| Gmail API | Реальный OAuth и `users.getProfile` успешно проверены пользователем; остаётся подтвердить отправителя, формат письма и свежий код Ozon. Offline тесты используют подставной API. |
| Browser → requests | Работоспособность новых session metadata и cookies для `www.ozon.ru`, срок действия и отсутствие перехода на SSO/antibot. |
| Карточка товара | Фактические JSON-виджеты и путь до каждого из 12 полей. Тесты сейчас используют синтетические структуры; `photosSeller`/`videosSeller` не подтверждены. |
| PostgreSQL end-to-end | Реальные INSERT, повторный запуск того же SKU, UPDATE без дубля и SELECT с проверкой значений. |

## Правила извлечения до получения реальной карточки

- Строго совпадающий SKU обязателен; данные соседнего товара не используются.
- Цена: первый корректный `offers.price`, затем `product.price`; конкретный коммерческий тип цены ещё не определён.
- `art_set`: артикул производителя → `art set` → комплектация → состав набора. Приоритет может потребовать уточнения после просмотра реальных характеристик.
- Фото и видео продавца читаются только из полей выбранного товара; фотографии отзывов не считаются фотографиями продавца.
- `has_rich_content` учитывает HTML в описании, `richContent` товара и отдельный виджет, привязанный к тому же SKU.

## Ограничения и бонус

Airflow и DataLens — необязательные бонусы после работающего основного сценария. Условия доступа к Ozon, допустимый объём запросов и тестовый аккаунт разумно согласовать с заказчиком. Cookies, OAuth-токены, коды подтверждения и диагностический HTML не должны попадать в Git. Диагностическая копия HTML проходит лишь частичное удаление чувствительных данных и требует ручной проверки перед передачей.

Порядок дальнейшей работы и критерии завершения: [`remaining-tasks.md`](remaining-tasks.md).
